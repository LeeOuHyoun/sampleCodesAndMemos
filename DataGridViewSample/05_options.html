2. 행 높이 조절 방법 정리

    
행 높이 설정은 모두 new DataGridView({...}) 에 넘기는 설정 객체 안에 넣는다. 다만 넣는 자리가 세 군데로 나뉜다. treeDocument(데이터)에는 넣지 않는다. 근거: DataGridView.js 의 DataGridViewLayout (getDefaultCellHeight / _applyCellHeight / getRowHeightFromCellHeight / getRowHeightFromCellContents).


    
2-1. 어디에 넣나

    


var grid = new DataGridView({
  treeDocument: treeDocument,

  1layoutOptions: {
    cellHeight: 32,
    layoutDensity: 'compact',
    rowSpacing: 0,
    getRowHeightFunction: function (rowID) { ... }
  },

  columns: [
    { text: '품번', dataIndex: 'tree' },
    { text: '비고', dataIndex: 'note', 2autoRowHeightFlag: true }
  ],

  3maxVisibleRowCount: 10
});

      
    
        
  • 1layoutOptions : 설정 객체 안의 하위 객체. 행 높이를 정하는 기본 자리다. 그리드를 만들 때만 넣을 수 있고(readOnly), 만든 뒤에는 grid.layout.키 = 값 으로 바꾼다.
    • 
        
  • 2컬럼 옵션 : columns 배열의 각 컬럼 객체. 그 컬럼 내용에 맞춰 행 높이를 자동으로 늘릴 때 쓴다.
    • 
        
  • 3그리드 옵션 : 설정 객체 최상위. 행 높이가 아니라 그리드 전체 높이를 정한다. 행 높이와 헷갈리기 쉬워서 같이 적었다.
    •

2-3. 예제

    

      

        
예제 1. 모든 행을 32px 로

        
layoutOptions.cellHeight 에 숫자를 준다. 26 보다 작게 주면 26 으로 되돌아간다.


new DataGridView({
  treeDocument: treeDocument,
  columns: columns,
  layoutOptions: { cellHeight: 32 }
});

      

      

        
예제 2. 넉넉한 화면 (comfortable)

        
행 기본 높이가 40px 이 된다. 이때 cellHeight 를 40 보다 작게 줘도 40 이다 (실제 높이 = max(cellHeight, 밀도 기본 높이)).


new DataGridView({
  treeDocument: treeDocument,
  columns: columns,
  layoutOptions: { layoutDensity: 'comfortable', rowSpacing: 2 }
});

      

      

        
예제 3. 만든 뒤에 높이 바꾸기

        
layoutOptions 는 생성할 때만 넣을 수 있다. 만든 뒤에는 grid.layout 에 직접 넣으면 바로 다시 그려진다.


grid.layout.cellHeight = 40;
grid.layout.layoutDensity = 'comfortable';
grid.layout.rowSpacing = 4;

      

      

        
예제 4. 특정 행만 높게 (getRowHeightFunction)

        
rowID 를 받아 높이(px)를 돌려준다. undefined 를 돌려주면 기본 높이. 행 데이터는 grid.model[rowID] 로 읽는다.


new DataGridView({
  treeDocument: treeDocument,
  columns: columns,
  layoutOptions: {
    getRowHeightFunction: function (rowID) {
      var node = grid.model[rowID];
      if (node && node.getAttributeValue('status') === '검토중') {
        return 50;
      }
      return undefined;
    }
  }
});

      

      

        
예제 5. 만든 뒤에 행별 높이 함수 넣기

        
실제 ENOVIA 앱에서 많이 쓰는 방식. 행 높이는 한 번 계산하면 저장해 두므로, 함수를 넣거나 데이터가 바뀐 뒤에는 resetRowHeights() 로 다시 계산시킨다.


grid.layout.getRowHeightFunction = function (rowID) {
  return rowID === 0 ? 60 : undefined;
};
grid.layout.resetRowHeights();

      

      

        
예제 6. 긴 글에 맞춰 자동으로 (autoRowHeightFlag)

        
컬럼에 autoRowHeightFlag: true 를 주면 그 컬럼 내용 높이에 맞춰 행이 커진다. 너무 커지지 않게 layoutOptions.rowMaxHeight 로 상한을 둘 수 있다.


new DataGridView({
  treeDocument: treeDocument,
  layoutOptions: { rowMaxHeight: 120 },
  columns: [
    { text: '품번', dataIndex: 'tree' },
    { text: '비고', dataIndex: 'note', typeRepresentation: 'multilineString', autoRowHeightFlag: true }
  ]
});

      

      

        
예제 7. 그리드 전체 높이 (행 높이 아님)

        
height 기본값 'inherit' 은 부모 요소 높이를 따른다. 부모 div 에 높이가 없으면 그리드가 안 보이므로, 높이를 주거나 maxVisibleRowCount 를 쓴다.


new DataGridView({
  treeDocument: treeDocument,
  columns: columns,
  maxVisibleRowCount: 10
});

      

    


    

      주의
      
    
        
  • layoutOptions 를 그리드 옵션 최상위에 풀어서 쓰면(new DataGridView({ cellHeight: 32 })) 적용되지 않는다. 반드시 layoutOptions: { ... } 안에 넣는다.
    • 
        
  • autoRowHeightFlag 컬럼이 있어도 getRowHeightFunction 을 직접 넣으면 직접 넣은 함수가 우선이고 자동 계산은 쓰이지 않는다.
    • 
        
  • 서버 사이드(virtuallyLoadAllModelItems) 모드에서는 autoRowHeightFlag 가 지원되지 않는다 (콘솔 경고 후 무시). 이때는 getRowHeightFunction 을 직접 구현한다.
    • 
        
  • 1장 실시간 설정의 "행 높이" 묶음에서 위 값들을 바꿔 보며 바로 확인할 수 있다.
    • 
      

    


    
3. 편집 방식 (컬럼 editionPolicy)

    
셀/콤보가 언제 편집기로 바뀌는지는 컬럼의 editionPolicy 로 정한다. 편집되려면 editableFlag: true 가 먼저 필요하다. 근거: DataGridView.getEditionManager, CollectionView.js 의 edition/* 클래스.

    


    
4. 그리드 생성자 옵션 — new DataGridView({ ... })

    
DataGridView 자체 옵션 + 상속받은 CollectionView, Controls/Abstract 옵션. 생성 후에도 grid.옵션 = 값 으로 바꿀 수 있다 (readOnly 표시 제외).

    


    
5. layoutOptions — new DataGridView({ layoutOptions: { ... } })

    
레이아웃(DataGridViewLayout) 객체를 만들 때 넘기는 옵션. 생성 후에는 grid.layout.옵션 = 값 으로 바꾼다.

    


    
6. 컬럼 옵션 — columns: [ { ... } ]

    
기본값은 DataGridView 의 defaultColumnDef 기준. defaultColumnDef 옵션으로 넘긴 값은 빠진 키만 기본값으로 채워지므로 일부 키만 넣어도 된다.

    


    
7. 컬럼 함수 옵션 (셀마다 다르게 할 때)

    
고정값 대신 함수를 넣으면 셀마다 다르게 정할 수 있다. 인자 cellInfos 에는 rowID, columnID, cellID, nodeModel(행 데이터), cellModel(셀 값) 등이 들어 있고, 함수 안의 this 는 그리드다.

    


    
8. typeRepresentation (셀 모양/편집기 종류)

    
컬럼의 typeRepresentation 에 넣는 값. Tweakers/assets/defaultTypeRepresentations.json + typeTemplates.json 기준. "기본 semantics" 는 따로 안 넣어도 적용되는 값.

    


    
9. semantics (컬럼 semantics / getCellSemantics 반환값)

    
편집기(Tweaker)에 그대로 전달되는 세부 옵션. Tweakers.js 의 TweakerBase / TweakerString / TweakerNumber / TweakerDate / TweakerBoolean publishedProperties 기준.

    


    
10. 하위 옵션 객체

    
그리드 옵션 중 객체로 넘기는 것들의 내부 키.

    


    
11. 필터 — treeDocument.setFilterModel({ dataIndex: { filterId } })

    
필터는 그리드 옵션이 아니라 TreeDocument 에 지정한다. 첫 트리 컬럼(dataIndex 'tree')의 키는 'label'. 사용 빈도는 webapps 전체 소스에서 센 값.

    


    
12. 툴바 — grid.setToolbar({ entries: [ ... ] })

    
툴바는 생성자 옵션이 없고 setToolbar(JSON) 으로만 만든다. 근거: Tweakers.js 의 GeneratedToolbar.

14. 이벤트 — grid.addEventListener('이벤트', function (event, cellInfos) { ... })

    

      DataGridView 의 addEventListener 는 CollectionView 에서 재정의되어 있어, 이벤트가 셀 안에서 발생하면 두 번째 인자로 그 셀의 cellInfos(cellID, rowID, columnID, cellModel, nodeModel, cellView)를 넘겨준다. 셀 밖이면 event 만 넘어온다.
      event.dsModel 은 그리드, event.options 에 추가 정보가 들어 있다. 그리드 영역 DOM 에 등록되므로 일반 DOM 이벤트(click 등)와 셀 편집기에서 버블링되는 이벤트도 모두 받을 수 있다.
      1장 실시간 설정 화면의 이벤트 로그에서 실제로 언제 발생하는지 확인할 수 있다.
