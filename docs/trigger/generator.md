# 채번기 (Object Generator) <Badge type="info" text="원본 분석" />

객체 이름(name)을 `PRT-000001` 처럼 접두어 + 일련번호로 자동으로 만드는 장치입니다. 트리거가 아니라 **business object 두 개** 로 설정하고, 코드나 생성 화면이 그 설정을 읽어 이름을 만듭니다.

::: info 근거
`mql/13.generator/*.mql` (59 개. Object / Number Generator 쌍과 type 별 묶음 파일), `mql/06.command/*` 의 `emxCreate.jsp` href. 코드 쪽: `jpo/emxLibraryCentralClassificationAttributesBase_mxJPO.java` (번호 증가 로직), `jpo/DECNameGeneratorBase_mxJPO.java`, `jpo/emxECPartBase_mxJPO.java` (generator 조회), `FrameworkUtil.autoName` 호출부 (`emxLifecycleBase`, `emxMemberListBase`, `emxDocumentCentralSubscriptionBase`, 프로젝트 JPO), `DomainObject.getAutoGeneratedName` 호출부 (`emxBusinessUnitBase`, `emxCompanyBase`), `3dspace/common/emxCreateBody.xsl`
:::

샘플: [03_relationship_role.mql](https://github.com/LeeOuHyoun/sampleCodesAndMemos/blob/master/SchemaSample/03_relationship_role.mql) (eService Object / Number Generator)

## 구조

```text
eService Object Generator   'type_MyPart'  ''      접두어, 접미어, 재시도 설정
   │  relationship 'eService Number Generator'
   ▼
eService Number Generator   'type_MyPart'  ''      다음 번호
```

| 항목 | 값 |
| --- | --- |
| name | 대상 type 의 **심볼릭 이름** (`type_MyPart`) |
| revision | 시리즈 이름. 한 type 에 규칙이 여럿이면 revision 으로 나눔 (OOTB 예: `type_CADModel` / `A Size`). 하나면 `''` |
| policy | `eService Object Generator` (두 객체 모두) |
| vault | `eService Administration` |

### 속성

| 객체 | 속성 | 뜻 |
| --- | --- | --- |
| Object Generator | `eService Name Prefix` | 접두어 (`PRT-`) |
| | `eService Name Suffix` | 접미어 |
| | `eService Retry Count` | 번호를 잠그지 못했을 때 다시 시도할 횟수 |
| | `eService Retry Delay` | 다시 시도 전 기다리는 시간 |
| | `eService Processing Time Limit` | 처리 제한 시간 |
| | `eService Safety Policy` | policy 심볼릭 이름 (`policy_MyPartPolicy`). 호출 때 policy 를 주지 않으면 쓰는 값으로 보입니다 <Badge type="danger" text="검증 필요" /> |
| | `eService Safety Vault` | vault 심볼릭 이름 (`vault_eServiceAdministration`). 위와 같은 용도로 보입니다 <Badge type="danger" text="검증 필요" /> |
| Number Generator | `eService Next Number` | 다음 번호. **자리수가 그대로 유지됨** (`000001` → `000002`) |

## 만들기

```text
add bus 'eService Object Generator' 'type_MyPart' ''
    policy 'eService Object Generator'
    vault  'eService Administration'
    'eService Name Prefix'           'PRT-'
    'eService Name Suffix'           ''
    'eService Retry Count'           '5'
    'eService Retry Delay'           '60'
    'eService Processing Time Limit' '60'
    'eService Safety Policy'         'policy_MyPartPolicy'
    'eService Safety Vault'          'vault_eServiceAdministration'
;
add bus 'eService Number Generator' 'type_MyPart' ''
    policy 'eService Object Generator'
    vault  'eService Administration'
    'eService Next Number' '000001'
;
add connection 'eService Number Generator'
    from 'eService Object Generator' 'type_MyPart' ''
    to   'eService Number Generator' 'type_MyPart' ''
;
```

`connect bus 'eService Object Generator' 'type_MyPart' '' relationship 'eService Number Generator' to 'eService Number Generator' 'type_MyPart' '';` 로 연결해도 같습니다.

::: warning name 은 심볼릭 이름
generator 는 **심볼릭 type 이름** 으로 찾습니다. `'MyPart'` 처럼 실제 이름으로 만들면 찾지 못합니다. type 의 심볼릭 이름이 `eServiceSchemaVariableMapping.tcl` 에 등록되어 있어야 합니다. [심볼릭 이름](/schema/#심볼릭-이름)
:::

## 번호가 만들어지는 방식

OOTB 코드(`emxLibraryCentralClassificationAttributes`)가 직접 번호를 뽑는 부분을 보면 아래 순서입니다. `FrameworkUtil.autoName` 도 같은 방식으로 보입니다. <Badge type="danger" text="검증 필요" />

1. `pushContext` 와 트랜잭션 시작
2. Number Generator 를 `lockForUpdate`. 실패하면 `Retry Delay` 만큼 쉬고 `Retry Count` 번까지 다시 시도
3. `eService Next Number` 를 읽고 1 을 더해 같은 자리수로 0 을 채워 저장
4. 잠금 해제, commit
5. 이름 = `Prefix` + 읽은 번호 + `Suffix`

여러 사용자가 동시에 만들어도 잠금 때문에 번호가 겹치지 않습니다. 자리수를 넘으면(`999999` 다음) 자리수가 하나 늘어납니다.

## 코드에서 쓰기

| 호출 | 돌려주는 것 |
| --- | --- |
| `FrameworkUtil.autoName(context, "type_MyPart", "policy_MyPartPolicy")` | **만들어진 객체 id** |
| `FrameworkUtil.autoName(context, "type_MyPart", "", "policy_MyPartPolicy", vault)` | 객체 id. 3 번째가 시리즈(revision) |
| `FrameworkUtil.autoName(context, "type_Route", null, "policy_Route", null, null, true, true)` | OOTB 는 이 형태의 반환값을 **이름** 으로 써서 `createObject` 에 넘김 |
| `DomainObject.getAutoGeneratedName(context, "type_MyPart", "")` | 이름만 (객체는 안 만듦) |

```java
String id = FrameworkUtil.autoName(context, "type_MyPart", "policy_MyPartPolicy");
DomainObject part = DomainObject.newInstance(context, id);
part.setAttributeValue(context, "Title", title);
```

- type, policy 모두 **심볼릭 이름** 을 넘깁니다. 실제 이름만 가지고 있으면 `FrameworkUtil.getAliasForAdmin(context, "type", realName, true)` 로 바꿉니다.
- `autoName` 은 객체를 바로 만들므로, 그 뒤 속성 설정과 연결까지 한 트랜잭션으로 묶습니다.
- generator 가 없는 type 이면 예외가 납니다. 이름을 직접 정하는 대안이 있으면 `try` 로 감쌉니다.

## 생성 화면에서 쓰기

`emxCreate.jsp` 의 URL 인자로 이름 입력 방식을 고릅니다.

```text
${COMMON_DIR}/emxCreate.jsp?form=MyPartCreateForm&type=type_MyPart&policy=policy_MyPartPolicy&nameField=autoname&createJPO=MyPartUI:createPart
```

| 인자 | 뜻 |
| --- | --- |
| `nameField=autoname` | 이름을 채번기로 만듦 |
| `nameField=both` | 직접 입력과 자동 생성 둘 다. 체크박스로 고름 |
| `autoNameChecked=false` | `both` 일 때 자동 생성 체크박스를 끈 채로 시작 |

form 필드 설정 `autoName`, `AutoName Checked` 로도 같은 체크박스를 그립니다 (`emxCreateBody.xsl`).
